# 동작 규격

[← README](../README.md)

고양이 조작, 말 걸기 문법, 브리핑, 캘린더 위젯, 상태별 보드의 상세 규격이다.

## 고양이 조작

| 조작 | 동작 |
|---|---|
| 왼쪽 클릭 | 입력 말풍선 열기/닫기 |
| 드래그 | 위치 이동. 위치는 설정에 저장돼 다음 실행에도 유지 |
| 우클릭 | 메뉴: 말 걸기 / 오늘 브리핑 / 새로고침 / 설정 / 종료. 새로고침은 states 캐시도 비운다 |
| 트레이 아이콘 더블클릭 | 오늘 브리핑 |
| 트레이 메뉴 `캘린더 위젯` | 위젯 보이기/숨기기 (체크 상태가 설정에 저장) |
| 트레이 메뉴 `상태별 보드` | 보드 위젯 보이기/숨기기 (체크 상태가 설정에 저장, 아래 절) |
| 트레이 메뉴 `보드 항상 위에 표시` | 보드의 바탕화면 층 ↔ 항상 위 전환 |
| 트레이 메뉴 `위젯 항상 위에 표시` | 바탕화면 층 ↔ 항상 위 전환. 위젯이 창에 가려 우클릭을 못 할 때 쓴다 |
| 트레이 메뉴 `로그 폴더 열기` | 탐색기로 `%APPDATA%\Catcretary\logs` 열기 |

캐릭터가 그려지지 않은 픽셀은 클릭이 뒤 창으로 통과한다. 말풍선도 카드 바깥은 통과한다.

## 캐릭터 상태

앱이 정하는 의미 상태와, 대기 중 스스로 하는 행동 두 층이다. 행동은 `Idle`/`Alert` 일 때만 끼어들고 끝나면 돌아온다.

| 상태 | 언제 | 클립 |
|---|---|---|
| `Idle` | 평소 | idle |
| `Listening` | 입력·확인 말풍선이 열려 있을 때 | paw |
| `Thinking` | Plane 호출 중 | clean 2 |
| `Done` | 등록·완료 처리 직후 (점프, 1회) | jump |
| `Alert` | 마감 지난 담당 항목이 남아 있는 동안 (빨간 배지) | scared |
| `Curious` | 마우스를 올리면, 또는 가끔 | idle 2 |
| `Groom` | 가끔, 드래그해서 내려놓은 직후 | clean |
| `Walk` | 6~14초마다 45% 확률로 제자리(드래그로 정한 자리) 좌우 ±140px 안을 산책. 방향에 맞춰 좌우 반전 | walk |
| `Sleep` | 6분간 아무 조작이 없으면. 클릭·말풍선·브리핑에 깬다 | sleep |
| `Scared` | 드래그로 들어 올리는 동안 | scared |

클릭 반응은 매번 같지 않다(1/3 확률로 점프 후 듣기, 나머지는 바로 듣기). 스프라이트가 없으면 코드로 그린
임시 고양이를 쓰고, 산책·반전·잠은 그대로 동작한다. 에셋을 넣는 방법은 [`Assets/pet/README.md`](../src/Catcretary/Assets/pet/README.md).

말풍선 문구는 전부 고양이 말투("~냥")다. 트레이 툴팁은 평문이다.

## 말 걸기

입력 말풍선에 쓴 문장은 아래 순서로 판정한다. 쓰기 명령은 모두 확인 말풍선에서 누른 뒤에만 Plane 에 쓴다.

| 순서 | 종류 | 예 | 확인 말풍선 |
|---|---|---|---|
| 1 | 항목 명령 | `SHOP2-3 완료`, `SHOP2-3 시작`, `SHOP2-3 취소`, `SHOP2-3에 메모: 로그인 오류 재현 필요`, `SHOP2-3 열어` | 열기 외에는 있음 |
| 2 | 프로젝트 생성 | `새 프로젝트 BLOG3 만들어줘, 식별자 BLOG3, 템플릿 SHOP2, 별칭 블로그 BLOG-III` | 있음 |
| 3 | 검색 | `로그인 오류 찾아줘`, `검색 결제 모듈` | 없음 (목록) |
| 4 | 브리핑 | `오늘 뭐 해야 해?`, `브리핑` | 없음 (목록) |
| 5 | 할 일 등록 | `SHOP 결제 모듈 분석 월요일부터 금요일까지, 급함 #분석 이번 사이클에` | 있음 |

### 할 일 등록

```
"SHOP 쇼핑몰 결제 모듈 분석 금요일까지, 급함"
  → 확인 말풍선: 프로젝트 [SHOP-II] 쇼핑몰 리뉴얼 / 제목 "결제 모듈 분석" / 마감 9/25 (금) / 우선순위 긴급
  → [등록] → Plane POST (담당자 = 나) → "SHOP2-3 등록했다냥"
```

문장에 프로젝트가 없으면 설정의 기본 프로젝트(`defaultProject`)에 넣는다. 확인 말풍선에 `○○ (기본)` 으로 표시하고,
다른 프로젝트 버튼도 같이 보여 바꿀 수 있다. 기본 프로젝트가 비어 있거나 등록 대상(멤버, 미보관, `excludedProjects` 밖)에 없으면
프로젝트 버튼만 보여주고 고르게 한다. Plane 항목은 반드시 프로젝트에 속하므로, 특정 업무에 속하지 않는 일반 할 일은
개인 프로젝트(예: identifier `ME`)를 하나 만들어 기본 프로젝트로 두고 쓴다. `TodoParser` 가 인식하는 표현:

| 종류 | 예 |
|---|---|
| 프로젝트 | identifier(`SHOP2`), 이름, `projectAliases` 별칭. 하이픈·공백·괄호 무시, 뒤의 조사(`에`, `에서`, `의`…) 제거 |
| 마감일 | `오늘` `내일` `모레` `글피`, `금요일`, `이번 주 수요일`, `다음 주`, `N일 후`, `M/D`, `M월 D일`, `YYYY-MM-DD`, `이번 달 말`, 뒤의 `까지` |
| 시작일 | 마감일과 같은 표현 뒤에 `부터` / `에서부터` / `~`. 예: `월요일부터 금요일까지`, `10/7~10/10`. 요일만 말해 마감이 시작보다 앞서면 마감을 한 주 뒤로 민다 |
| 라벨 | `#버그 #UI`. 등록할 때 그 프로젝트 라벨 이름과 대소문자 무시 대조. 없는 라벨은 만들지 않고 빼고 알린다 |
| cycle | `이번 사이클`, `현재 스프린트`, `사이클에 넣어`. 등록 뒤 진행 중인 cycle(`cycle_view=current`)의 첫 번째에 넣는다. 없으면 알리고 등록은 유지 |
| 우선순위 | `긴급/급함/ASAP` → urgent, `중요/우선` → high, `보통` → medium, `낮음/여유/천천히` → low |
| 제목 | 위 표현을 뺀 나머지. 끝의 `해줘`, `등록`, `하기` 등 제거 |

`사이클 타임 분석` 같은 제목과 섞이지 않도록 cycle 은 앞에 `이번`/`현재` 가 오거나 뒤에 `에`/`로` 가 와야 인식한다.

### 항목 명령

문장이 `{identifier}-{번호}` 로 시작하고, 그 identifier 가 워크스페이스에 실제로 있을 때만 명령으로 본다(대소문자 무시).
없는 identifier 면 일반 등록 문장으로 처리한다. 항목은 `GET /work-items/{KEY}-{N}/` 으로 찾는다.

| 꼬리말 | 동작 | 보내는 state |
|---|---|---|
| `완료` `끝` `done` `닫아` | 상태 변경 | 프로젝트의 `completed` 그룹 첫 state |
| `시작` `진행` `착수` | 상태 변경 | `started` 그룹 첫 state |
| `취소` `cancel` | 상태 변경 | `cancelled` 그룹 첫 state |
| `메모:` `댓글:` `코멘트:` + 내용 | 댓글 작성. 줄마다 `<p>` 로 감싸 `comment_html` 로 보낸다 | |
| 없음, `열어` | 기본 브라우저로 항목 페이지 | |

상태 명령은 꼬리말이 16자 이하일 때만 인식한다. 이미 같은 그룹 상태면 바꾸지 않고 알린다.

### 검색

`work-items/search/?search=…&workspace_search=true` 로 이름·번호·프로젝트 identifier 부분 일치를 찾는다(내가 멤버인 프로젝트만, 최대 8건).
내 담당 항목은 브리핑 항목을 그대로 쓰고, 아니면 식별자로 한 건씩 다시 조회해 상태·마감을 채운다. 결과 목록은 브리핑 목록과 같아서
✓ 로 완료 처리하거나 줄을 눌러 Plane 페이지를 연다.

### 프로젝트 생성

쉼표로 나눈 조각마다 `식별자` / `템플릿` / `별칭` / `이름` 중 하나로 읽는다. 그 밖의 조각에서 `새`, `프로젝트`, `만들어줘` 를 뺀 것이 이름이다.

| 항목 | 규칙 |
|---|---|
| 이름 | `& + , : ; $ ^ } { * = ? @ # \| ' < > . ( ) % ! -` 금지 (Plane 1.4.2 `FORBIDDEN_IDENTIFIER_CHARS_PATTERN`, 이름에도 적용). 같은 이름이 있으면 되묻는다 |
| 식별자 | 영문 대문자·숫자 12자 이내. 말하지 않으면 이름의 영문·숫자로 만든다. 이름이 한글뿐이면 되묻는다. 이미 있는 식별자면 되묻는다 |
| 권한 | 워크스페이스 Admin 또는 Member. 만든 사람은 서버가 프로젝트 Admin 으로 넣고 기본 state 5개를 만든다 |
| 템플릿 | 지정한 프로젝트의 state(이름이 없는 것만, 이름·색·그룹), 라벨(계층 무시), 멤버(role `15` Member)를 복사한다. 기본 state 는 지우지 않는다. 일부 실패해도 생성은 성공으로 보고 실패 수를 알린다 |
| 별칭 | `별칭 A B` 또는 `A/B`. 만든 뒤 `projectAliases` 에 저장 |

## 브리핑 시각

| 동작 | 규격 |
|---|---|
| 판정 주기 | 30초마다 확인 |
| 조건 | 오늘 아직 안 띄웠고, 설정 시각이 지났고, (평일만 옵션이면) 평일일 것 |
| 늦게 켠 날 | 09:00 이 지난 뒤 PC 를 켜도 그날 첫 판정에서 바로 뜬다 |
| 표현 | 고양이가 뛰고, 말풍선에 요약 한 줄(30초, 새로 배정·새 소식 건수 포함). 말풍선 클릭 → 목록 패널(항목별 ✓ 완료 처리, 항목 줄 클릭 → 기본 브라우저로 Plane 페이지) |
| 목록 머리 | 프로젝트마다 `담당 N/전체 M · 진행률 P% · cycle 요약`. 진행률 = `completed` 그룹 수 ÷ (초안·`cancelled` 를 뺀 전체). 이미 받은 항목으로 계산해 추가 호출이 없다 |
| 기록 | `%APPDATA%\Catcretary\state.json` 의 `lastBriefingKey` = `날짜@시각`. 설정에서 시각을 바꾸면 키가 달라져 그날 다시 뜬다 |
| 기준 회전 | 브리핑 시각마다 `baselineIds ← announcedIds`, `prevAnnounceAt ← lastAnnounceAt` 으로 한 칸 민다. 그래서 그날 하루는 "지난 브리핑 이후" 가 기준이다 |

## 새로 배정·새 소식

| 항목 | 규칙 |
|---|---|
| 새로 배정 | 내 담당 미완료 중 `baselineIds`(지난 브리핑 때 내 담당 id)에 없던 것. 목록 맨 위 `새로 배정` 섹션. 기록이 없는 첫날은 만들지 않는다 |
| 남이 수정 | 목록 응답의 `updated_by` 가 내가 아니고 `updated_at` 이 기준 시각 이후. 추가 호출 없음 |
| 새 댓글 | 댓글은 항목 `updated_at` 을 바꾸지 않아서(서버 소스 확인) 항목마다 최근 댓글 5개를 조회한다. 마감이 가까운 순으로 최대 20건. 내가 쓴 댓글은 뺀다 |
| 기준 시각 | `prevAnnounceAt`. 없으면 24시간 전 |
| 표시 | 항목 줄 아래 초록 글씨(`새 댓글 · 작성자: 앞 40자`, `○○ 님이 수정`) |
| 알림 | 주기 새로고침에서 앞 조회에 없던 댓글·변경이 생기면 말풍선 `새 소식 N건`(20초, 누르면 목록). 입력·확인 중에는 띄우지 않는다. 앱 시작 직후 첫 조회는 알리지 않는다 |

## 캘린더 위젯

미완료 항목을 월간 달력에 그린다. 우클릭 메뉴 `표시 범위` 로 내 담당만(기본) / 담당자 무관 전체를, `프로젝트` 로 볼 프로젝트를
고른다(여러 개 선택 가능, 아무것도 고르지 않으면 모든 프로젝트). 대상 프로젝트는 브리핑과 같다(멤버, 미보관, `excludedProjects` 밖). 기본은 바탕화면 층(모든 창 아래)이라 다른 창을 가리지 않는 대신
창을 띄워 두면 보이지 않는다. `항상 위에 표시` 를 켜면 다른 창 위에 뜬다.

| 항목 | 규격 |
|---|---|
| 날짜 칸 | 칸 왼쪽 위에 `11/12` 처럼 월/일. 오른쪽에 공휴일 이름 또는 음력 |
| 표시 날짜 | `target_date`(마감일). 마감일이 없으면 `start_date`. 둘 다 없으면 상태 줄의 `날짜 없음 N` 에만 센다 |
| 기간 표시 | 메뉴 `시작일~마감일 기간 모두 표시` 를 켜면 시작일부터 마감일까지 막대 하나로 이어 그린다. 주가 바뀌면 다음 줄에서 이어진다. 표시 중인 달 밖에 걸친 부분만 흐리게 |
| 주 focus | 메뉴 `이번 주 가운데 (5주 보기)` 를 켜면 월 대신 5주를 보여주고 이번 주를 3번째 줄에 둔다. 달이 섞이므로 흐리게 처리하지 않는다. 제목은 `2026년 9월 – 10월` |
| 항목 줄 | 왼쪽 색 막대 = 우선순위(긴급 빨강, 높음 주황, 보통 노랑, 낮음 파랑, 없음은 state 색). 마감 지난 항목은 글자가 빨강. 툴팁에 담당자 |
| 넘침 | 칸 높이로 들어갈 줄 수를 계산한다. 항목은 먼저 시작하는 것·긴 것·마감 지난 것·우선순위 순으로 겹치지 않는 가장 위 줄에 넣고, 줄이 모자라 못 그린 항목은 해당 날 날짜 옆에 `+N` (툴팁에 목록) |
| 항목 클릭 | 기본 브라우저로 Plane 페이지 |
| 항목 끌기 | 막대를 다른 날 칸에 놓으면 잡은 날과 놓은 날의 차이만큼 시작일·마감일을 함께 옮긴다(기간 길이 유지, 없던 날짜는 만들지 않음). 끄는 동안 놓일 칸에 테두리, 상태 줄에 새 날짜. 제자리에 놓으면 취소. 화면을 먼저 바꾸고 `PATCH` 하며 실패하면 되돌린다 |
| 날짜 칸 더블클릭 | 고양이 입력 말풍선을 `M월 D일 ` 이 채워진 상태로 연다 |
| 음력 | 칸 오른쪽 위 `월.일`, 윤달은 `윤6.1`. 음력 1일은 굵게. 공휴일에는 그 자리에 공휴일 이름을 쓰고 음력은 툴팁 |
| 공휴일 | 신정, 삼일절, 어린이날, 현충일, 광복절, 개천절, 한글날, 성탄절, 설날·추석 연휴, 부처님오신날, 대체공휴일 |
| 새로고침 | `refreshIntervalMinutes` 마다(최소 5분) 백그라운드 조회. 실패하면 말풍선 없이 상태 줄에 `연결 실패`. 보드·캘린더에서 등록·수정·상태 변경·날짜 이동을 하면 1.5초 뒤 그 프로젝트 항목만 다시 받고, 마지막 쓰기 30초 뒤 전체를 다시 조회한다. 조회 도중 쓰기가 있었으면 그 주기 조회 결과는 쓰기 전 값일 수 있어 버린다. 말풍선 명령 뒤에는 바로 다시 조회하고, 조회 중이면 끝난 뒤 한 번 더 조회한다. Plane 웹에서 바꾼 것은 다음 주기 또는 새로고침 아이콘에서 반영 |
| cycle | 진행 중인 cycle 기간의 칸 아래에 얇은 띠. 툴팁에 `프로젝트 · 이름 남은 N/M건 (기간)`. 여러 프로젝트 cycle 이 겹치면 띠 하나에 툴팁 여러 줄. 메뉴로 끈다 |
| 자정 | 1분마다 날짜를 확인해 오늘 표시를 옮긴다. 이번 달을 보던 중이면 새 달로 넘어간다. 주 focus 모드에서 주를 옮기지 않았으면 새 주가 가운데로 온다 |

대체공휴일 규칙: 설날·추석 연휴가 일요일 또는 다른 공휴일과 겹치면 겹친 날 수만큼 연휴 다음 첫 평일 비공휴일(2014~).
어린이날은 토·일·다른 공휴일과 겹칠 때(2014~). 삼일절(2022~), 광복절·개천절·한글날(2021~), 부처님오신날·성탄절(2023~)은
토·일과 겹칠 때. 2024~2027년 공휴일표와 대조해 일치를 확인했다.

우클릭 메뉴는 Windows 기본 메뉴가 아니라 위젯 테마(밝게/어둡게)를 따르는 Catcretary 스타일이다(`Themes/Controls.xaml`).
메뉴에서 바꾼 값과 위치·크기는 바로 `config.json` 의 `widget` 에 저장된다. 다음 실행 때 같은 자리·크기로 뜬다.
저장된 자리가 모니터 구성 변경으로 화면 밖이면 주 모니터 우상단으로 옮긴다. Windows 시작 시 자동 실행은 설정 창의
`Windows 로그인 시 자동 실행` 을 켜면 된다(고양이·위젯 함께).

바탕화면 고정 방식: `WS_EX_TOOLWINDOW`(Alt+Tab 제외), 소유자를 바탕화면 창(`Progman`)으로 지정, `WM_WINDOWPOSCHANGING`
에서 Z 순서를 항상 맨 아래로 돌린다(항상 위 모드에서는 이 처리를 끄고 `Topmost` 로 둔다). 탐색기가 재시작되면 소유자와 함께 창이 파괴되므로 3초 뒤 다시 만든다.

## 상태별 보드

트레이 메뉴 `상태별 보드` 또는 캘린더 위젯 우클릭 `상태별 보드 보이기`. 캘린더 위젯과 같은 방식의 바탕화면 위젯이다:
제목 표시줄·작업 표시줄 버튼이 없고, 바탕화면 층 고정(`DesktopPin`), 탐색기 재시작 시 3초 뒤 다시 만들기, 테마·투명도·위치 고정·항상 위를
우클릭 메뉴로 바꾼다. 보이기 상태는 저장돼 다음 실행 때 다시 뜬다. 데이터는 브리핑 새로고침이 받아 온 것을 그대로 쓴다.
추가 호출은 빠른 추가·카드 수정에서 담당자·라벨 패널을 처음 펼칠 때(수정은 라벨 있는 카드를 열 때도) 그 프로젝트의 멤버·라벨 조회 2회뿐이다(새로고침 아이콘을 누르기 전까지 재사용).

| 항목 | 규격 |
|---|---|
| 제목 줄 | 빈 곳 드래그 = 위치 이동(고정 모드가 아닐 때). 오른쪽에 범위·프로젝트 ComboBox, `완료·취소 카드` 체크, 새로고침 아이콘 |
| 가장자리 드래그 | 크기 조절 (최소 480×300, 고정 모드가 아닐 때) |
| 열 | 프로젝트 하나를 고르면 그 프로젝트의 state(`sequence` 순). `모든 프로젝트` 면 state 그룹 5개(백로그 / 할 일 / 진행 중 / 완료 / 취소). 열 너비는 창 너비를 나눠 쓰고, 열당 180 보다 좁아지면 가로 스크롤 |
| 범위 | 내 담당 / 전체(담당자 무관). 기본은 전체 |
| 카드 | identifier-번호, 제목(2줄), 담당자, 마감(지나면 빨강). 왼쪽 테두리 색 = 우선순위. 열 안은 마감일 → 우선순위 순 |
| 완료·취소 | `완료·취소 카드` 를 끄면(기본) 카드를 숨기고 건수에 `(숨김)`. 열은 남아 있어 끌어다 놓을 수 있다 |
| 카드 끌기 | 다른 열에 놓으면 상태를 바꾼다. state 열이면 그 state, 그룹 열이면 그 항목 프로젝트의 해당 그룹 첫 state. 그 그룹 state 가 없는 프로젝트면 바꾸지 않고 상태 줄에 알린다. 화면을 먼저 바꾸고 `PATCH` 하며 실패하면 되돌린다 |
| 카드 클릭 | 카드 자리에 수정 칸이 열린다. 빠른 추가와 같은 제목 입력과 칩(우선순위·날짜·담당자·라벨)에 지금 값이 채워진다. Enter 면 바뀐 필드만 `PATCH` 하고 응답 항목으로 보드·캘린더 위젯을 바로 바꾼 뒤 그 프로젝트 항목을 다시 받고, Esc 면 취소. 입력 칸에 입력하는 동안 들어온 새로고침 결과는 입력 칸을 떠날 때 그린다(포커스·한글 조합이 끊기지 않게). 저장 중에 다른 카드를 누르면 상태 줄에 안내만 하고 무시한다. 프로젝트·상태는 여기서 바꾸지 않는다(상태는 카드 끌기). 라벨이 있는 카드는 열 때 그 프로젝트의 멤버·라벨을 받는다 |
| 카드 우클릭 | 우클릭 메뉴 맨 위에 그 항목 `Plane 에서 열기`(기본 브라우저), `수정` |
| 빠른 추가 | 각 열 아래 `＋ 새 작업 항목` → 입력 칸에 제목을 쓰고 Enter 면 그 열의 상태로 만든다(Plane 의 빠른 추가와 같이 칸이 열린 채로 다음 항목을 받는다). 그룹 열이면 입력 칸의 ComboBox 로 프로젝트를 고르고(처음에는 `defaultProject`, 없으면 첫 프로젝트) 그 프로젝트의 해당 그룹 첫 state 로 만든다. 만든 카드는 바로 보드·캘린더 위젯에 넣은 뒤 그 프로젝트 항목을 다시 받아 맞춘다 |
| 빠른 추가 세부 값 | 제목 아래 칩 `우선순위` / `날짜` / `담당자` / `라벨`. 누르면 입력 칸 안에 선택 패널이 펼쳐진다(다시 누르거나 Esc 로 접기). 우선순위: 긴급·높음·보통·낮음·없음. 날짜: 달력에서 하루를 고르면 마감일, 드래그·Shift+클릭으로 기간을 고르면 시작일~마감일, `오늘`·`내일`·`이번 주 금`·`지우기` 단축. 담당자·라벨: 프로젝트 멤버·라벨 체크 목록(여러 개). 담당자 기본값은 범위가 `내 담당` 이면 나. Enter 는 패널에 포커스가 있어도 등록, Esc 는 패널이 펼쳐져 있으면 패널을, 아니면 입력 칸을 닫는다. 등록에 성공하면 제목과 세부 값을 모두 비운다 |
| 우클릭 메뉴 | (카드 위에서 누르면 위 `카드 우클릭` 항목이 맨 위에 붙는다) 새로고침, 캘린더 위젯 보이기, 표시 범위, 프로젝트, 완료·취소 카드 표시, 테마, 투명도, 항상 위에 표시, 위치·크기 고정, 보드 숨기기 |
| 저장 | 범위·프로젝트·테마 등 설정과 위치·크기는 `config.json` 의 `board` |

Plane 웹(1.4.2 Community)의 workspace 보기는 표 레이아웃만 있어(`WorkspaceActiveLayout` 이 spreadsheet 만 그림) 여러 프로젝트를
상태별·달력으로 보려면 이 보드와 위젯을 쓴다. 한 프로젝트 안에서는 Plane 웹의 Kanban·Calendar 레이아웃도 된다.

## 분류 규칙

내 담당(`assignees` 에 `users/me` 의 id 포함) 이면서 state group 이 `backlog`/`unstarted`/`started` 인 항목만
대상이다. 한 항목은 위에서부터 처음 맞는 섹션 하나에만 들어간다.

| 순위 | 섹션 | 조건 |
|---|---|---|
| 0 | 새로 배정 | 지난 브리핑 때 내 담당이 아니었음 (위 절) |
| 1 | 마감 지남 | `target_date` < 오늘 |
| 2 | 오늘 마감 | `target_date` = 오늘 |
| 3 | 이번 주 마감 | `target_date` ≤ 오늘+7일 |
| 4 | 진행 중 | state group = `started` |
| 5 | 우선순위 높음 | priority = `urgent` 또는 `high` |
| 6 | 그 외 미완료 | 나머지 |
