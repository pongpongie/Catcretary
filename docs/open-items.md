# 남은 확인 사항

[← README](../README.md)

아직 실제로 확인하지 않은 동작과 알려진 제약이다.

- 0.3.0 의 쓰기 호출은 사내 서버에서 아직 실행해 보지 않았다: 프로젝트 생성, state·라벨 생성, 프로젝트 멤버 추가, 댓글 작성,
  `cycle-issues` 추가, `started`/`cancelled` 상태 변경, `start_date`·`labels` 를 담은 항목 생성. 경로와 본문은 1.4.2 소스
  (`apps/api/plane/api/`) 기준이다. 읽기 호출(`users/me`, `fields=` 필터, `cycle_view=current`, 검색, 식별자 조회, 댓글·라벨·프로젝트 멤버 조회)은
  사내 서버에서 응답을 확인했다.
- 캘린더 막대 끌기와 보드 카드 끌기는 빌드와 데이터(서버 항목 58건, 열 분류)까지만 확인했고, 실제로 마우스로 끌어 보지 않았다.
  날짜 `PATCH`(`start_date`·`target_date`)도 서버에서 아직 실행해 보지 않았다.
- 바탕화면 층 모드(`항상 위에 표시` 끔)에서 위젯 막대 끌기·보드 카드 끌기가 되는지 확인하지 않았다. 안 되면 `항상 위에 표시` 를 켜고 쓴다.
- 보드 빠른 추가는 입력 칸 화면(state 열·그룹 열)과 포커스까지 확인했고, Enter 로 실제 항목을 만들어 보지 않았다(`state` 를 담은 생성 요청 미실행).
- 빠른 추가 세부 값 패널(우선순위·날짜·담당자·라벨)은 가짜 데이터로 밝게/어둡게 화면을 PNG 로 렌더링해 배치만 확인했다.
  실제 창에서 칩·달력·체크 목록을 마우스로 눌러 보지 않았고, 달력의 선택 기간 강조도 화면에서 확인하지 않았다.
  담당자 여러 명·라벨을 담은 생성 요청도 서버에서 실행해 보지 않았다.
- 보드 카드 수정은 가짜 데이터로 수정 칸 화면(밝게/어둡게)과 값 채우기·저장 호출 경로, 우클릭 위치의 항목 판정까지 확인했다.
  실제 창에서 카드를 눌러 보지 않았고, 수정 `PATCH`(이름·우선순위·날짜 지우기·담당자·라벨)도 서버에서 실행해 보지 않았다.
- 달력은 WPF 기본 Calendar 라 어둡게 테마에서도 밝은 카드로 그린다(템플릿 안 색이 밝은 배경 기준으로 고정).
- 테마 메뉴·ComboBox·보드는 밝게/어둡게 화면을 PNG 로 찍어 확인했다. 마우스를 올렸을 때 강조, 하위 메뉴를 마우스로 여는 동작은 직접 눌러 보지 않았다.
- 확인 시점에 진행 중인 cycle 이 있는 프로젝트가 없어 cycle 띠·요약은 실제 데이터로 그려 보지 않았다.
- `cycle_view=current` 는 서버가 `start_date <= now <= end_date` 로 판정한다. 시간대(UTC/KST)에 따라 시작·끝 날이 하루 어긋날 수 있다.
- 기본 프로젝트(`defaultProject`)는 build 까지만 확인했다. 말풍선 등록·설정 창 ComboBox·보드 빠른 추가의 처음 선택은 실제 창에서 눌러 보지 않았다.
- 앱의 프로젝트 생성은 공개 범위를 지정하지 않아 서버 기본값으로 만들어진다. 개인 할 일 프로젝트는 Plane 웹에서 비공개로 바꾸는지 확인한다.
- 템플릿 복사는 멤버 role 을 알 수 없어 모두 Member(15)로 넣는다. 원래 Admin 이던 사람은 Plane 에서 직접 올려야 한다.

- 위젯의 바탕화면 보기(Win+D) 동작은 아직 확인하지 않았다. 소유자를 `Progman` 으로 두는 방식은 Windows 10 에서 널리 쓰이지만
  Windows 11 에서 위젯이 숨지 않는지는 실제로 눌러 봐야 한다.
- 위젯은 미완료 항목만 보여준다. 완료·취소된 항목은 달력에 남지 않는다.
- 선거일·임시공휴일은 계산하지 않는다. `widget.extraHolidays` 에 직접 넣는다. 음력 계산은 .NET `KoreanLunisolarCalendar`
  지원 범위(~2050년)까지다.

- 스프라이트 PNG 는 라이선스(재배포 금지) 때문에 저장소에 없다. 새로 clone 하면 `Assets/pet/README.md` 대로
  받아 넣기 전까지 임시 도형 고양이로 동작한다.
- `TodoParser` 는 규칙 기반이라 별칭에 없는 표현("쇼핑 사이트")은 프로젝트를 못 찾고 되묻는다. 별칭을 늘리거나,
  나중에 LLM(Claude API 또는 로컬 `claude -p`)을 붙이는 선택지가 있다.
- 완료·시작·취소는 각 프로젝트의 해당 그룹 state 중 첫 번째로 보낸다.
- 여러 사람이 담당인 항목, epic/하위 작업 계층은 평면 목록으로만 보여준다.
- 항목 페이지 URL 은 `/{slug}/projects/{projectId}/issues/{issueId}` 형식이다. 최신 Plane 은 `/{slug}/browse/{KEY}/` 로
  redirect 한다. 사내 서버 버전에서 실제로 열리는지는 아직 확인하지 않았다.
